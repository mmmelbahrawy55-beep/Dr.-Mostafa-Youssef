# د. مصطفى يوسف — Dr. Mostafa Youssef

موقع كامل لاستشاري تغذية علاجية ومدرب لياقة: يفتح بالعربي (RTL) افتراضيًا مع تبديل سهل للإنجليزي، حسابات عملاء، اشتراكات مدفوعة عبر **فودافون كاش / إنستاباي** بفحص إشعار التحويل، ولوحة تحكم إدارية كاملة للمحتوى والعملاء والمدفوعات والإعدادات.

## التشغيل

```bash
npm install
npm run dev        # API :4000 + الواجهة :5173  (http://127.0.0.1:5173)
npm run dev:api    # السيرفر فقط
npm run dev:web    # الواجهة فقط
npm run build      # tsc + vite build → dist/
npm run build:server  # حزمة السيرفر لـ Vercel → build/server.mjs
npm run preview    # معاينة نسخة الإنتاج
npm run typecheck  # فحص أنواع TypeScript (الواجهة + السيرفر)
node scripts/smoke.mjs            # 61 اختبارًا وظيفيًا (SMOKE_BASE لاختيار الهدف — يرفض الإنتاج افتراضيًا)
node scripts/security-smoke.mjs   # 13 اختبار أمان: 2FA، الجلسات، النسخة الاحتياطية
npm run backup                    # نسخة كاملة من Redis → data/backups/
RESTORE_CONFIRM=YES node scripts/restore.mjs data/backups/<file>.json
node scripts/generate-icons.mjs   # إعادة توليد أيقونات PWA
```

## التخزين — Upstash Redis

كل البيانات (المستخدمون، المدفوعات، الاشتراكات، المحتوى، الإعدادات، سجل العمليات) **وملفات الصور** (لقطات الإيصالات ومكتبة الوسائط) محفوظة في **Upstash Redis**، عشان تفضل ثابتة بعد كل إعادة نشر على Vercel — مجلد `/tmp` على Vercel بيتصفّر مع كل عملية نشر.

المتغيرات المطلوبة في إعدادات مشروع Vercel:

| المتغيّر | الوصف |
| --- | --- |
| `KV_REST_API_URL` | عنوان REST الخاص بـ Upstash (من موارد Marketplace) |
| `KV_REST_API_TOKEN` | توكن الكتابة |
| `JWT_SECRET` | سر توقيع الجلسات — **لازم يكون ثابتًا** وإلا كل نسخة تشغيل هتعمل جلسات تانية |
| `REDIS_PREFIX` | مساحة أسماء المفاتيح (افتراضي `dm`). استخدم `dev` محليًا حتى لا تتلوّث بيانات الإنتاج |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | بيانات مدير الموقع عند أول تشغيل فقط (اختياري) |

> محليًا: ضع `KV_REST_API_URL` و `KV_REST_API_TOKEN` في `.env.local` (الملف متجاهل في git). تُحمّل هذه المفاتيح فقط، ولا تُحمّل أي متغيّر آخر من ملف مسحوب بـ `vercel env pull`.

إذا حذفت كل مفاتيح `dm:*` من Redis، يُعاد إنشاء حساب الإدارة والمحتوى تلقائيًا عند أول تشغيل.

## بيانات الدخول

لا يوجد باسورد افتراضي ثابت في الكود. عند أول تشغيل على قاعدة فارغة:

- لو `ADMIN_EMAIL` و `ADMIN_PASSWORD` مضبوطين في البيئة، يُنشأ الحساب بهما.
- وإلا يتولّد باسورد عشوائي قوي ويُكتب في `data/admin-password.txt` (وعلى Vercel في `/tmp` مع سطر في اللوج).

بعد أول دخول: غيّر الباسورد من **حسابي → بياناتك الشخصية** (بيطلب الباسورد الحالي)، وده بيلغي كل الجلسات القديمة تلقائيًا.

> المجلد `data/` مستثنى من git. لا تحفظ أي باسورد في الكود أو README.

## نظام الدفع

1. العميل يختار الباقة ويُدخل مبلغ العملية + رقم المرسل + رقم العملية + **رقم المستلم كما هو في الإيصال**، ويرفع صورة الإيصال.
2. الخادم يراجع الإيصال بقواعد ذكية (بدون أي مفتاح أو نموذج لغوي): كون الملف صورة حقيقية، الأبعاد والحجم وتناسق الشكل، تطابق المبلغ **بالظبط** مع سعر الباقة، تطابق رقم المستلم مع رقم فودافون كاش/إنستاباي المعتمد (والتأكد إن المرسل ليس المستلم)، صيغة رقم المحفظة، صحة رقم العملية (طول، أرقام، ليست رقم المحفظة)، ومنع تكرار نفس الصورة أو نفس المرجع بحجز ذرّي (atomic claim) يمنع الطلبات المتزامنة — إضافة إلى حد 8 محاولات رفع في الساعة لكل حساب. الواجهة بتضغط الصورة تلقائيًا، والحد الأقصى للرفع 4 ميجا (حد Vercel).
3. صورة الإيصال تُحفظ في Redis **قبل** إنشاء سجل الدفع، فلا يظهر دفع بدون صورة.
4. **لو كل الفحوصات نجحت والتفعيل التلقائي مفعّل (الافتراضي)** → الاشتراك يتفعّل في نفس اللحظة (`auto_approved`). أي ملاحظة واحدة → الدفعة تدخل قيد المراجعة (`pending`) مع أسباب عربية يقرأها المدير، **ولا يوجد رفض تلقائي أبدًا**.
5. المدير يراجع الصورة ويوافق أو يرفض مع ملاحظة، ويظهر أثر العملية في `سجل العمليات`. التفعيل التلقائي يمكن تعطيله من «الإعدادات».

المبالغ محفوظة كأعداد صحيحة بالجنيه المصري، والتواريخ بصيغة ISO.

## لوحة التحكم

- **نظرة عامة**: الإيرادات (الإجمالي / النهار / الشهر)، المدفوعات المعلقة، العملاء، الاشتراكات النشطة والقريبة من الانتهاء، ورسم بياني لآخر 6 شهور.
- **المدفوعات**: فلترة وبحث، معاينة صورة الإيصال في نافذة، موافقة/رفض مع ملاحظة.
- **العملاء**: إنشاء/تعديل/إيقاف، تفاصيل شاملة (اشتراكات، دفعات)، منح اشتراك يدوي.
- **المحتوى**: تحرير كل المجموعات (البرامج، الخدمات، آراء العملاء، النتائج، المقالات، الأسئلة، المؤهلات) بالعربية والإنجليزية.
- **نظام البرنامج**: من «المحتوى → الباقات → تعديل» تقدر تكتب النظام الكامل لكل باقة: الملخص، المستوى، النتائج، خطوات البداية، الأسابيع، عادات كل أسبوع، قالب الوجبات، تقسيم التدريب، وقواعد المتابعة — عربي وإنجليزي.
- **نصوص الموقع**: تحرير أي نص في الموقع مع تجاوز قيم النسخة الأصلية (overrides) وإعادة تعيينها.
- **الرسائل**: وارد رسائل نموذج التواصل مع رد واتساب وحذف.
- **الصور والوسائط**: رفع ومراجعة ونسخ الرابط وحذف — **بطاقة تفاصيل لكل صورة**: مين رافعها، تاريخ الرفع، الحجم، الأبعاد (بكسل)، نوع الملف، الرابط، و**في أي مكان على الموقع مستخدمة** (باقة، خدمة، مقال، صورة الغلاف).
- **الإعدادات**: بيانات التواصل، أرقام المحافظ، التعليمات، إعلان علوي، صورة الغلاف، وتفعيل/تعطيل الموافقة التلقائية.
- **الأمان**: تفعيل/إيقاف التحقق بخطوتين (TOTP + أكواد احتياطية)، عرض كل الأجهزة المسجلة وإخراج أي جهاز، وتنزيل نسخة احتياطية JSON.
- **تصدير البيانات**: أزرار CSV للمدفوعات والعملاء والاشتراكات (بترميز UTF-8 مناسب لإكسل العربي).
- **سجل العمليات**: كل عملية بفعلها ومنفّذها ووقتها، **مشروحة بالعربي** (المبلغ، الباقة، طريقة الدفع، عدد الصفوف…) مع بحث وفلتر بالإجراء وشريط عدّادات لكل نوع، **وإمكانية حذف أي عملية أو مسح السجل كله** بتأكيد على خطوتين — الحذف متاح للمدير فقط، والحذف نفسه مش بيتسجل عشان السجل ميعيدش تعبئ نفسه. **زرار «معاينة» على كل صف** يفتح نافذة فيها جملة واحدة تشرح اللي حصل بالظبط، صورة الإيصال أو الصورة المرتبطة (إن وجدت)، البيانات الكاملة للعملية، ورابط يوديك للصفحة اللي الموضوع ده فيها.

## التقنية

- **الواجهة**: Vite 8 · React 19 · TypeScript · Tailwind CSS v4 · Framer Motion · React Router 7 · Lucide
- **الخادم**: Express 5 · **Upstash Redis** (عبر REST) · JWT في كوكي httpOnly · multer للرفع المؤقت
- **النشر**: Vercel — `api/index.js` يستورد `build/server.mjs` (حزمة ESM عبر esbuild)
- **اللغة**: طبقات `ar`/`en` مع دعم الاتجاه (RTL/LTR) تلقائيًا، والافتراضي **العربية** مع تذكير اختيار المستخدم.
- **الأمان**: تحقق بخطوتين TOTP مع أكواد احتياطية، جلسات مخزّنة في Redis قابلة للإبطال لكل جهاز، قفل تدريجي بعد محاولات الدخول الفاشلة، رؤوس `nosniff`/`X-Frame-Options`/`Referrer-Policy`/HSTS، فحص محتوى الصور، حجز ذرّي للإيصالات، وتسجيل كل عملية إدارية.
- **الوسائط**: كل الصور محلية بصيغة WebP (بدون اعتماد على Unsplash)، مع PWA وservice worker للعمل offline وتثبيت الموقع على الموبايل.

## نظام البرامج والاشتراكات

- كل باقة — الحالية أو أي باقة جديدة تتضاف من لوحة التحكم — ليها **نظام برنامج كامل**، مش مجرد قائمة مميزات: ٤ أسابيع، وجبات، تمارين، عادات، ومتابعة.
- المشترك صاحب اشتراك نشط بيلاقي تبويب **«برنامجي»** في `/account`، فيه تقدم الباقة، أسبوعه الحالي، خطة الأسابيع كاملة، قالب الوجبات، تقسيم التدريب، وقواعد المتابعة، مع زر طباعة/PDF وزر متابعة واتساب.
- الباقة الجديدة بتاخد قالب نظام جاهز من ٤ أسابيع أول ما تتضاف، وبعدها تعدّله من لوحة التحكم. الباقات القديمة بيتم إضافة النظام لها تلقائيًا مرة واحدة عند أول تشغيل بعد التحديث، من غير ما يلمس أي تعديل عمله المدير.
- جدول مقارنة الباقات وصفحة «شوف اللي جوه الباقة» بيتبنوا تلقائيًا من بيانات النظام والمميزات، فأي باقة جديدة بتظهر في المقارنة والصفحة بدون أي كود.
- المشترك بيشوف النظام الكامل فقط بعد تفعيل الاشتراك؛ الزائر بيشوف ملخص وعينة الأسبوع الأول.

## الأمان والنسخ الاحتياطي

- **التحقق بخطوتين**: من `/admin/security` — امسح رمز QR أو اكتب المفتاح في Google Authenticator، وأكّد بكود، وهتظهر ١٠ أكواد احتياطية مرة واحدة. الدخول بعد كده بيطلب الباسورد + الكود.
- **الجلسات**: كل جهاز مسجّل بيظهر في «حسابي» وفي صفحة الأمان، مع زر إخراج. تغيير الباسورد بيلغي كل الجلسات ويعمل جلسة جديدة للجهاز الحالي.
- **قفل المحاولات**: ٥ محاولات فاشلة من نفس الجهاز/الحساب = قفل ١٥ دقيقة (مع حد إجمالي أعلى للحساب).
- **سجل العمليات**: يشمل الدخول، تغيير الباسورد، تفعيل/إيقاف 2FA، إخراج الأجهزة، تنزيل النسخ الاحتياطية، وكل قرارات الدفع والمحتوى.
- **النسخة الاحتياطية**: زر في صفحة الأمان ينزّل JSON بكل الجداول (بدون الصور)، و`npm run backup` ياخد نسخة كاملة من Redis (بما فيها الصور) إلى `data/backups/`. الاستعادة تحتاج `RESTORE_CONFIRM=YES` وتتحقق من اسم مساحة المفاتيح قبل الكتابة.
- **حد الرفع**: ٤ ميجا، مع ضغط تلقائي للصور في المتصفح ورسالة 413 واضحة.
